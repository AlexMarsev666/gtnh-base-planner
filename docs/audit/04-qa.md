## Подтверждённые ошибки

### Q1. Шаблон из ссылки `#s=` теряется при перезагрузке — High

Дубликат **A4** (`01-architecture.md`), повышен до High: данные пользователя теряются, а ссылка уже удалена из адресной строки.
`src/ui/siteSession.ts:49-54` + `:83-86`. Воспроизведено scratch-тестом `f`: после `initSiteSession` и `pagehide` ключ шаблона в
хранилище отсутствует; появляется только после первой правки. **Проверено ведущим.**
Исправление: сразу после `replaceSite(shared)` вызвать `saveStoredSite`.

### Q2. Нечитаемый сохранённый план молча заменяется планом по умолчанию — High

- **Где:** `src/ui/session.ts:65` (`loadStoredPlan()`), `:105-123`; `src/share/persist.ts:59-92`; для шаблонов —
  `src/share/sitePersist.ts:34-61`.
- **Доказательство:** `readStoredPlan` возвращает `{ error, backupKey }` (комментарий: «so the UI can say … a copy was kept»),
  но UI вызывает только `loadStoredPlan`, который их отбрасывает; `startAutosave` пишет текущее значение (план по умолчанию)
  через 300 мс. Scratch-тест `g`: в хранилище `some-removed-multiblock`, count 12 → после старта `coke-oven 4`, копия только в
  `gtnh-planner:v1:backup-…`. **Проверено ведущим** (`codec.ts:115-120` бросает на неизвестном id).
- **Последствия:** удаление/переименование сгенерированного мультиблока, будущая смена версии формата или Q3 стирают план без
  сообщения; резервную копию в UI не найти.
- **Исправление:** `readStoredPlan` в `initSession`, уведомление с «восстановить/скачать копию», не автосохранять до решения.

### Q3. Приложение пишет план, который потом не может прочитать (лимит 64 КБ к разным формам) — Medium (High для хранилища)

- **Где:** `src/share/persist.ts:187` (`planFromJson`: `text.length > MAX_PAYLOAD_BYTES`), `:105-113` (`saveStoredPlan` без
  проверки размера), `:181-183` (`planToJson` с отступами). `MAX_PAYLOAD_BYTES = 64 * 1024` (`binary.ts:4`).
  **Проверено ведущим.**
- **Воспроизведение (scratch `c`):** ручной план с N блоками: N=600 → JSON 67 037 символов → «Plan file is too large»;
  N=2000 → в хранилище 89 728 символов → при следующей загрузке отказ и сброс (Q2). Ссылка работает при любом N.
- **Последствия:** «Download JSON» при >~560 ручных блоках создаёт файл, который приложение не открывает; >~1460 — план
  сбрасывается при перезагрузке.
- **Исправление:** один и тот же лимит на запись и чтение (или 1 МБ, как `MAX_SITE_FILE_BYTES`), явная ошибка при записи.

### Q4. «Copy link» выдаёт ссылку на шаблон, которую само приложение не откроет — Medium (High для больших импортов)

- **Где:** `src/share/siteCodec.ts:368` (кодер проверяет длину **сжатого** base64) против `:375` (декодер ограничивает
  **распакованный** JSON 64 КБ). **Проверено ведущим.**
- **Воспроизведение (scratch `c`):** 256 групп, 255 связей, 400 ресурсов → JSON 202 339 байт → `encodeSite` OK (13 946 символов) →
  `decodeSite`: «Plan data is too large.» Порог примерно 100 групп + 500 связей.
- **Исправление:** в `encodeSite` проверять несжатый размер и предлагать скачать JSON, либо поднять лимит декодирования шаблона.

### Q5. Импорт GTNH падает целиком из-за одного значения вне диапазона или управляющего символа — Medium

- **Где:** `src/import/gtnhplanner.ts:270` (`ratePerSecond`), `:232`, `:723` (`machineCount`), `:676`, `:722` (имена не
  очищаются), `:849` (`validateSiteState` без try/catch); комментарий `:46-48` обещает пропуск битых записей.
- **Воспроизведение (scratch `b`):** `ratePerSecond: -1` или `1e13`, `machineCount: 1e7`, `displayName: "A\nB"`, имя рецепта с
  `\t`, id с `\u0000` → разбор проходит, BUILD падает с `PlanFormatError` без указания узла. Сумма ставок может превысить
  `MAX_RATE` (`:766`).
- **Исправление:** ограничивать/очищать значения в `parseGtnhProject` или ловить ошибку по записи.

### Q6. Ключи `constructor`/`__proto__` в таблицах сопоставления машин; молча выпадающие группы — Low

`src/data/gtnhplanner-machines.ts:174,186` (обычные объекты), `src/import/gtnhplanner.ts:709-710` (`if (!def) continue` без учёта в
`report.skipped`). Scratch `a`: `multiblockForName('constructor')` → `function`; цепочка из 2 узлов → 1 группа. Все текущие
алиасы указывают на существующие мультиблоки (проверено скриптом), но тестом это не закреплено.
Исправление: `Object.hasOwn`/`Map`, учитывать выпавшие узлы.
