# 3E. Ориентация юнита: переворот и зеркало на каждый юнит (дизайн-заметка)

Статус: на согласовании у пользователя. Основание: ревью `gtnh-expert` по вики (Steam Separator, IEM) и
`MTEEnhancedMultiBlockBase.java:163-165` (GT 5.09.54.205).

## Что меняется для пользователя

- Каждый юнит в машинном виде может быть **перевёрнут вверх ногами** и/или **отражён**, независимо от соседей.
  Упаковщик (задача 3D) сам подбирает такие сочетания. Пример: два Steam Separator в одном кубе 5×5×5, IEM ×4
  размером 15×7.
- Если машина в GT не разрешает поворот или отражение, планировщик их не предлагает.
- Старые планы, шаблоны и ссылки открываются без изменений: юнит без нового поля стоит как раньше.

## Модель

**Варианты определения.** Сейчас зеркало реализовано как преобразование def целиком (`mirroredDef`,
мемоизировано, переворачивает легенду, стороны люков и зоны). Расширяю это до четырёх вариантов:

| variant | что это                            | преобразование локальных координат |
| ------- | ---------------------------------- | ---------------------------------- |
| 0       | как в каталоге                     | —                                  |
| 1       | зеркало по X (как `mirror` сейчас) | x → sx−1−x                         |
| 2       | вверх ногами (крен 180°)           | x → sx−1−x, y → sy−1−y             |
| 3       | отражение по вертикали             | y → sy−1−y                         |

Крен 180° вокруг оси взгляда контроллера геометрически равен «зеркало X + зеркало Y». Значит, четыре варианта —
это все сочетания двух независимых флагов `flipX`, `flipY`. Рыскание (`rotation` 0–3) остаётся отдельно.
Итого 16 ориентаций. Крен 90° и «лёжа на боку» сюда не входят, они в бэклоге.

- `orientedDef(def, variant)`: обобщение `mirroredDef`, мемоизировано, дважды применённое возвращает исходный
  объект. `flipY` меняет местами `up`/`down` в `disallowFaces`/`allowFaces`, переворачивает слои, `resize` по Y
  (Distillation Tower) и зоны.
- `Unit.variant?: 0 | 1 | 2 | 3`, отсутствует = 0. Плановое `mirror` остаётся значением по умолчанию для
  юнитов без варианта: действующий вариант = `variant ?? (mirror ? 1 : 0)`. Старые данные дают ровно ту же сцену.
- Модельные функции и дальше получают один базовый def, а для каждого юнита берут `orientedDef(def, variant)`
  через единый помощник (`defOfUnit`). Затронуты geometry (`unitCells`, `controllerFacing`), walls, hatches
  (sites, floor, validity), layout (`shapes`/`computePairOk` — ключ кэша пары дополняется вариантами), scene и
  site/group. Кэши, уже привязанные к объекту def, продолжают работать, потому что варианты мемоизированы.
- «Люк не смотрит в землю» и «клетка перед контроллером свободна» уже считаются в мировых координатах, поэтому
  верны и для перевёрнутого юнита. Это проверяется тестами.
- Сторона входа Oil Cracker и прочие «руковые» правила идут за вариантом, потому что зоны и регионы переезжают
  вместе с клетками (так уже работает `mirroredDef`).

## Допустимые ориентации по машинам

- Новое поле def `orientations?: { flipX?: false; flipY?: false }`: какие флаги GT запрещает. Отсутствует =
  разрешено всё (умолчание GT).
- Источник — переопределения `getInitialAlignmentLimits` (около 30 классов). Читаем их генерически в
  `tools/gt-source/` по шаблонам лямбд, которые нашёл эксперт: только горизонтально, без крена, без флипов,
  только стоя. Сверяем со списком эксперта. Дамп игры не нужен.
- Машины «только стоя» (Coke Oven) и «без крена» получают `flipY: false`, «без флипов» — `flipX: false`.

## Формат

- JSON плана и шаблона: у юнита в `manualUnits` появляется необязательное поле `variant` (1–3).
- Ссылка: в компактном массиве юнита `[x, y, z, r]` поле `r` кодирует `r + 4·variant` (0–15). Старые ссылки
  (0–3) читаются как раньше. Проверка значения расширяется до 0–15.
- Фикстуры старых данных кодируются байт в байт, это проверяет существующий тест.

## Чего здесь нет (задача 3D)

Поиск перекрытий по всем смещениям и парам ориентаций. 3E только делает варианты возможными и сохраняемыми;
упаковщик в 3E по-прежнему пробует то, что пробует сейчас (плюс плановое зеркало). Ручная расстановка
(`manualUnits`) получает варианты сразу.

## Порядок работы

1. Данные: `orientations` из исходников. Агент `developer`, ревью `gtnh-expert`.
2. Модель + формат: `orientedDef`, `Unit.variant`, проводка по модели, кодеки. Агент `developer`, ревью
   `algorithms-reviewer` и `qa-reviewer`.
3. UI: переключатели «перевернуть» и «отразить» для выбранного юнита в ручном режиме. Агент `developer`, ревью
   `architecture-reviewer`.
4. Затем 3D.
