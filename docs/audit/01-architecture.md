## Подтверждённые ошибки

### A1. Шаблон не расширяется после изменения count/limits/hatches группы — Medium

- **Где:** `src/ui/siteEditing.ts:70-96` (`growAfterBuild`); вызовы `src/ui/GroupInspector.svelte:65-69`, `src/ui/siteCommands.ts:46-47`.
- **Доказательство:** `patch()` вызывает `growAfterBuild(id)` **до** `updateSite(...)`. Svelte-стор вызывает нового подписчика
  синхронно с текущим значением; текущая сборка соответствует ещё не изменённой группе, поэтому
  `JSON.stringify(pg.group) === JSON.stringify(g)` истинно, `done = true`, и `grownFor` считается по старому состоянию — без
  изменений. Наблюдение снято до того, как придёт новая сборка. Scratch-скрипт агента: `consumed on INITIAL call`.
  Тестов на `growAfterBuild` нет. **Проверено ведущим.**
- **Воспроизведение:** почти заполненный шаблон → выбрать группу → в инспекторе поднять count с 1 до 50 → после пересборки
  группа выходит за край шаблона, шаблон не растёт. Второй путь: машинный вид, count 12 → «Add to template»: на
  `siteCommands.ts:46` группы ещё нет в `site`, `!g` → `done = true`; рост только по оценке одного блока (`grownForNew`).
- **Последствия:** функция «расширить шаблон, когда группа перестала помещаться» срабатывает только случайно (если сборка
  уже шла).
- **Исправление:** подписываться после записи в стор, либо пропускать начальный синхронный вызов и ждать сборку группы,
  отличной от состояния до патча. Добавить тест.

### A2. Отмена диалога импорта не отменяет импорт — Medium

- **Где:** `src/ui/ImportDialog.svelte:92-120`; Esc — `src/ui/App.svelte:122`.
- **Доказательство:** Esc/Cancel ставит `importOpen = false` (компонент уничтожается), но `build()` продолжает
  `await importSite(...)`, затем `replaceSite(next); appMode.set('site'); … if (optimizeAfter) void optimizeAfterImport(next);`.
  Флага отмены и прерывания задачи нет.
- **Воспроизведение:** вставить большой проект GTNH Planner → Build → сразу Esc. Через несколько секунд текущий шаблон
  заменяется импортом и запускается Optimize.
- **Последствия:** шаблон перезаписан после явной отмены (откатывается через Undo, но уведомление без ссылки Undo).
- **Исправление:** флаг `cancelled` при размонтировании/Cancel и отмена задачи в контроллере воркера.

### A3. Отброшенный или упавший Arrange/Optimize оставляет «Arranging…» до 2 минут; правки во время прогона не отображаются — Medium

- **Где:** `src/ui/siteCommands.ts:58-71`, `src/ui/siteWorkerController.ts:220-231`, `src/ui/siteWorker.ts:51-54,65-67`.
- **Доказательство:** `notify(..., 120000, 'arrange')`; `catch { return; }` глотает любой reject, включая ответ воркера
  `{error}`; `if (get(site) !== s) return;` молча выбрасывает результат; ни одна ветка не вызывает `clearSlot('arrange')`.
  Пока arrange в работе, сборки правок стоят в очереди (`inFlight !== null`). Бюджет Optimize — 10 с (`optimize.ts:53`).
- **Воспроизведение:** Optimize (запускается и автоматически после импорта) → сдвинуть группу стрелками → ~10 с сцена не
  реагирует → результат выброшен, уведомление висит до 2 минут, ошибка не показана.
- **Последствия:** потерянная оптимизация, «зависшее» сообщение, невидимые сбои.
- **Исправление:** `clearSlot('arrange')` на каждом раннем выходе; показывать ошибку; разрешить сборке прерывать arrange.
- Совпадает с находкой прошлого аудита (тесты и безопасность, №2).

### A4. Шаблон, открытый по ссылке `#s=`, не сохраняется — Medium

- **Где:** `src/ui/siteSession.ts:52-55` против `:80-86`; порядок запуска — `src/ui/appSession.ts:18-22`.
- **Доказательство:** `initSiteSession` делает `replaceSite(shared); clearSiteHash();`, и только в `.then` запускается
  `startSiteAutosave`, где первое значение пропускается (`if (first) { first = false; return; }`). Других вызовов
  `saveStoredSite` нет. Машинный аналог (`session.ts:120`) первое значение не пропускает. **Проверено ведущим.**
- **Воспроизведение:** пустой сохранённый шаблон → открыть `…#s=<ссылка>` → шаблон показан, хэш очищен → без правок
  перезагрузить → пусто, ссылки в адресной строке уже нет.
- **Последствия:** открытый по ссылке шаблон теряется при перезагрузке.
- **Исправление:** после `initSiteSession` один раз сохранить загруженное значение, если оно отличается от хранилища.

## Риски

- **A5. Машинный пайплайн работает в режиме шаблона — Medium.** `src/ui/App.svelte:56,62-65`: `$build` читается без условия
  (`const def = $derived($build.def)` и `$effect`), поэтому упаковка, хэтчи и маршрутизация машины выполняются синхронно на
  главном потоке при старте в режиме шаблона и при каждом переключении `connectBelow`. **Проверено ведущим** (подписка
  безусловна; стоимость зависит от размера плана). Исправление: читать `$build` только при `!siteMode`.
- **A6. Побочные эффекты `get(siteBuild)` и состояние модуля переживает подписку — Low–Medium.**
  `src/ui/sitePipeline.ts:22-27,55-56,71-76,103-127`, `siteCommands.ts:42`, `siteEditing.ts:42,75`. `get()` запускает сборку
  всего шаблона; `idleTimer`, задача в работе и `lastPipes` при остановке стора не сбрасываются. Сценарий: открыть другой
  шаблон, пока трубы не проложены → бледные трубы прежнего шаблона поверх нового. Связано с прошлой находкой: «Add to template»
  из машинного вида при ни разу не открытом шаблоне ставит группу в угол, потому что `get(siteBuild).build === null`
  (**проверено ведущим** в прошлом аудите).
- **A7. `whenBuilt` может сработать на сборке предыдущего шаблона — Low.** `src/ui/siteCommands.ts:92-100,128-129`:
  `isBuildOf` сравнивает только число и id групп, а импорт нумерует `g1…gn`. Импорт с тем же числом групп → Optimize
  стартует до показа импортированной раскладки.
- **A8. Выбор порта и сцена из разных снимков — Low.** `src/ui/App.svelte:72-75,83-87`: индекс порта берётся из `$site`, а
  сцена — из возможно устаревшей сборки.
