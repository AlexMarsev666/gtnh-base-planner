# Два отдельных общих люка крекера: исправление диагностики

## Воспроизведение

План пользователя `D:/Downloads/gtnh-site-site (3).json` сохранён как
`docs/fixtures/user-shared-cracker-overload.json`, с изменением только форматирования.
У группы g9 два Oil Cracking Unit HV в вертикальной паре. Hydrogen и Steam требуют
два отдельных общих люка (`unitIds: [0, 1]`); четыре подачи сырья и четыре продукта
переведены в Auto. Мультижидкостные люки в этом плане не используются.

Реальная полная сборка до исправления воспроизвела все **33 предупреждения** из запроса:
11 неразмещённых люков, отсутствующие ресурсы и повторные нарушения региональных минимумов.
Сохранённые назначения не менялись. Три новые отрицательные регрессии сначала упали:
общая граница возвращала 14 вместо 16, не учитывала явное общее назначение в проверке
дубликатов и оставляла 33 предупреждения вместо одной причины.

## Причины и исправление

Общая проверка считала каждый ресурс один раз и сравнивала физические люки с суммой
вместимостей контроллеров. Но явный общий люк заменяет корпус каждой машины: каждый
из двух катализаторных люков расходует два места. Требуется **16 мест**:
восемь для входных жидкостей, четыре для продуктов, два для энергии и два для обслуживания.
Доступны **14 мест**, по семь на машину. Размещение всех ресурсов невозможно даже в Auto.

Перегрузка конкретной машины в этом файле отсутствовала: вручную назначены только
два общих катализатора. Поэтому старое подавление производных ошибок не срабатывало.
Поиск допустимого распределения не находил ни одного варианта и оставлял только
структурные заполнители, вызывая длинный список отсутствующих ресурсов.

Изменения:

- `groupDemandBound` считает каждый явный общий люк по числу существующих владельцев.
  Повторные назначения одного слота не раздувают границу; исчезнувшие владельцы игнорируются.
- Доказанная общая перегрузка выбирает частичное размещение без перебора других упаковок.
  Его приоритет сохраняет энергию, обслуживание и явно запрошенные общие люки.
- При общей перегрузке показывается одна её причина вместо производных сообщений
  о неразмещённых ресурсах и минимумах. Независимые ошибки клеток, ролей, тиров и корпусов
  продолжают проверяться.

Ожидаемое сообщение начинается с:
`Group demand: at least 16 hatch slots required; total structure capacity 14 (2 controllers).`
Слово slots обозначает места в конструкциях контроллеров, а не число уникальных блоков.

Исходный JSON пользователя, количество машин, роли, тиры, назначения и настройки трассировки
не изменены. Это исправление диагностики и частичного размещения; оно не делает перегруженный
план полностью подключённым. Копия с раздельными катализаторами из предыдущего ответа
не удовлетворяет уточнённому требованию пользователя и не является решением этого случая.

## Критерии приёмки

- Во всей сборке приложенного плана ровно одно предупреждение о 16 местах при вместимости 14.
- Hydrogen и Steam размещены в двух разных физических люках, каждый служит обеим машинам.
- Энергия и обслуживание присутствуют у обеих машин; документ не изменяется сборщиком.
- Допустимая схема с теми же двумя общими люками и меньшим числом остальных ресурсов
  собирается без предупреждений.
- Неверная физическая клетка люка продолжает вызывать отдельную ошибку даже при перегрузке.
- В браузере одна причина видна после загрузки и перезагрузки; Both machines сохраняется
  для обоих катализаторов, ошибок JavaScript нет.
