## Перебор С2 на каталоге

Тестовый помощник `src/model/site/fixtures/crackingCapacity.ts` перебирает три оси, четыре
шага (общая грань, касание, зазор один и два блока) и два относительных поворота (0/180°).
Это полный перебор этих **24 кандидатов**, а не всех возможных координат. Совместимость геометрии
прошли 22, размещение 14 одиночных люков — **20**. У каждой машины ровно 7 люков:
2 сырья + 1 агент + 2 выхода + энергия + обслуживание, остаются 18 корпусов.
Ни один люк не занимает общую клетку. Десять ресурсов покрыты один раз.

Помощник решает отдельную задачу покрытия клеток, без `buildGroup` и `placeResourceHatches`.
Результаты проверяются независимым структурным валидатором; затем обычным роутером
и проверкой доступа/окончательных сторон. Все 20 свидетелей трассируются без предупреждений.

| Пример                             | Начало второй машины | Поворот | Блоки структуры | Блоки труб |
| ---------------------------------- | -------------------- | ------- | --------------- | ---------- |
| Стопка по Y                        | `[0, 2, 0]`          | 0°      | 69              | 357        |
| Ряд с зазором по X                 | `[6, 0, 0]`          | 0°      | 84              | 382        |
| Минимум среди найденных свидетелей | `[0, 0, 2]`          | 180°    | 69              | 333        |

Ряд по X с общей боковой стеной (шаг 4, поворот 0°) не подходит.
С2 больше не фиксирует X/Y/Z и не устанавливает `limitsLocked`; наличие общего ресурсного люка
не требуется. С2б требует сообщение **15 нужно, 14 вмещается** для одиннадцати жидкостей.
С2в сравнивает стоимость найденной алгоритмом допустимой раскладки с независимо полученными
и трассируемыми свидетелями, сначала по структуре, затем по трубам.

## Изменения этапа 1

- `casingConstraints.ts`: вместимость вычисляется по реальным клеткам и всем счётчикам
  корпусов, без завышенных ресурсами минимумов. Для крекера **25 − 18 = 7**.
  Общая клетка расходует счётчики всех физических владельцев, даже если `unitIds` неполон;
  откат восстанавливает каждого владельца.
- `group.ts`, `resourcePlacement.ts`: исходные структурные требования отделены от
  увеличенных спросом. При доказанной нехватке обязательные интерфейсы размещаются первыми.
  Частичный результат оценивается по отсутствию энергии/обслуживания, остальных обязательных
  интерфейсов и только затем ресурсных люков. Сравнение альтернатив в `resolveLayout`
  сохраняет этот приоритет.
- `types.ts`, `groups.ts`: числовая диагностика доходит до предупреждений сборки.
  С1: **12 люков нужно, вместимость 7; 25 клеток, 18 должны остаться корпусами**, разбивка
  по видам, энергия и обслуживание сохранены. С2б дополнительно получает нижнюю оценку
  группового спроса 15 против 14; это необходимое ограничение, не алгоритм распределения.
- Добавлены независимые положительные/отрицательные проверки ёмкости, нескольких счётчиков,
  общей клетки и обязательного обслуживания; регрессия при выборе частичного расположения.
  Работающие адаптеры и старые тесты сохранены.
- Исправлена обнаруженная регрессия поиска: приоритет частичных результатов сохраняется,
  а для поиска по геометрическим ограничениям остаётся порядок наиболее ограниченных клеток.
  Существующие таймауты импорта не повышались.
- Выполнен `npm run format`, в том числе для `tools/gt-source/rc2-source-hashes.json`.
  Содержимое JSON не изменилось; после нормализации оно совпадает с сохранённым в теге.

## Остановка

сохраняют старую модель: это причина оставшихся красных С2/С2в и предмет этапа 2.
Перебор свидетелей находится только в тестах и не подменяет алгоритм приложения.
Флаг зеркала, перераспределение ресурсов и экономный выбор кандидатов не реализованы.

Дизайн этапа 2 вынесен отдельно в `docs/plan-v3-stage-2-design.md`, объём меньше страницы.
После отчёта работа останавливается до подтверждения пользователя.

не выполнялись. Полный unit-прогон может читать прежние регрессионные фикстуры;
игровой стенд, JVM и сервер не запускались.
