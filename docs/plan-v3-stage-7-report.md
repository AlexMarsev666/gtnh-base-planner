# Этап 7: документация для обновления

Подготовлен [UPDATING.md](UPDATING.md): порядок снятия дампа следующей версии GTNH,
проверки отчёта конвертера до `--write`, записи каталога, переноса затронутых правил и приёмки.
В корневом [README.md](../README.md) исправлена устаревшая версия beta-3, уточнено происхождение
сохранённых форм и добавлены ссылки на инструкцию и статусы ограниченной поддержки.

## Что зафиксировано

- GTNH/GT5U/StructureLib, source commits, dev-JAR checksums и версия экстрактора — по существующим
  locks. Константа `build.mjs: TAG` и RC2 hash guards не переключаются параметром запуска автоматически.
- Карта существующих RC2-адаптеров: файлы кода и данных, формы/секции, роли и счётчики, необходимые
  для проверки при смене версии. Отдельная таблица конкретных ID специальных люков.
- Сохранение исторических RC2-свидетельств и честных ограничений; одни shape hints или исходники
  не объявляются игровой проверкой новой версии. Перенос применяется к изменившимся адаптерам,
  без нового полного аудита каталога.
- Совместимость ID, неявных размеров, ролей, output slots, unitId/unitIds, тиров и старых планов.
  Один жидкостный люк — один ресурс, общая клетка учитывается у каждой обслуживаемой машины.
- Команды приёмки, существующий список property-теста, эталоны и прежние бюджеты.

Документ содержит команды будущего обновления, но они в этапе 7 не выполнялись. Смена версии,
дамп, `*-rc2.mjs`, native, probes, симуляция, поиск рецептов, зеркало юнита и аудит Boldarnator
не запускались. Новых зависимостей, тестов и изменений runtime в этапе 7 нет. Код и данные этапа 6
не менялись; `outputs/` остаётся отдельным неотслеживаемым каталогом.
