## Underground depth

При глубине 3 горизонтальные подземные магистрали оказываются на y = −3. Причина подтверждена в
`router.ts`, функции `searchNeat`: горизонтальные шаги при y < 0 запрещены на любой другой глубине.
Вертикальные подводы разрешены; поверхность используется как резерв. Распределения магистралей между
уровнями −1, −2 и −3 сейчас нет. Существующий тест `router.test.ts` также явно закрепляет один слой.

Для ожидаемого пользователем поведения нужна отдельная доработка маршрутизатора: трактовать глубину
как доступный подземный диапазон, разрешить переходы между слоями и детерминированно выбирать их при
конфликтах. Потребуются регрессии с пересекающимися независимыми сетями, проверкой отсутствия их
соединения, предела глубины, повторяемости и поверхностного обхода при исчерпании всех слоёв. После
изменения проверить эталонные метрики и вид в подземном просмотре. Одна новая кнопка этого не решит.

Проверки текущей реализации: `userRefinery.test.ts` — 2/2, `router.test.ts` — 8/8.

Реализация приложения, назначения пользователя и бюджеты поиска в этой проверке не изменялись.

## Уточнение по приложенному файлу `gtnh-site-site (2).json`

После первоначального отчёта пользователь предоставил текущий файл из `D:/Downloads`.
Полная сборка воспроизвела ровно указанное предупреждение. Hydrogen и Steam имеют
`unitIds: [0, 1]`: каждый общий люк занимает ёмкость обеих машин. У Machine 1 дополнительно
три подачи и три продукта, итого восемь жидкостных назначений; у Machine 2 исходно четыре.

Перенос только Нафты и Light Steam-Cracked Naphtha даёт шесть жидкостных назначений каждой машине,
то есть по одной перегрузке. Поэтому прежний совет для первого эталона к этому файлу неприменим.

Проверенный вариант назначения:

- Hydrogen: Machine 1, вместо Both machines.
- Steam: Machine 2, вместо Both machines.
- Нафта (`fluid:resource`): Machine 2.
- Light Steam-Cracked Naphtha: Machine 2.

Получается пять жидкостных и два обязательных люка на машину. Реальная полная сборка показала
ноль предупреждений по всему плану и 102/102 подключённых терминала. Все десять ресурсов крекера
размещены; энергия и обслуживание сохранены на обеих машинах. В исходном перегруженном варианте
97/97 терминалов не доказывали полноту: часть запрошенных люков не была размещена.

Исправленная копия: `outputs/gtnh-site-site-2-cracker-fixed.json`. В ней изменены только четыре
указанных назначения; исходный файл, геометрия, роли и остальные настройки сохранены.
Это вариант с раздельными катализаторными люками. Сохранение обоих катализаторов общими при всех
восьми остальных назначениях требует 12 жидкостных мест суммарно, а после обязательных люков
доступны только 10. Одним перераспределением между этими двумя машинами это не исправить.

## Требование пользователя: оба катализатора общие

Пользователь уточнил: Hydrogen и Steam должны оставаться общими. Копия с раздельными
катализаторами не удовлетворяет этому требованию и не является принятым исправлением.
Назначения `unitIds: [0, 1]` в исходном файле сохраняются.

В текущей модели два отдельных общих катализаторных люка вместе с энергией и обслуживанием
оставляют по три места на остальные жидкости: шесть мест при восьми ресурсах. Удаление
предупреждения без изменения физического размещения нарушило бы ограничения конструкции.

Есть другой вариант для проверки: один общий мультижидкостный входной люк с обоими катализаторами.
Публичный исходник MTEOilCracker на закреплённом RC2 commit `a3e1e11241a814c9fa0dd0973d5699548428f689`
проверен непосредственно: строки 320–337 читают все катализаторные жидкости из MTEHatchMultiInput
средней колонны. Такой люк занимает одно место каждой машины, поэтому после обязательных люков
остаётся по четыре места на остальные жидкости. Это необходимый расчёт вместимости;
совместное размещение и трассировка такого варианта планировщиком ещё не проверены.

Текущая модель планировщика связывает ресурс с отдельным люком. Поддержка нескольких ресурсов
в одном физическом люке требует изменения модели, размещения и подключений. До реализации нужно
уточнить, допустим ли один общий мультижидкостный люк или требуются два отдельных общих люка.
Код приложения на этом шаге не изменялся.

Окончательное уточнение пользователя: нужны два отдельных общих люка; мультижидкостные
люки для сырья в данном плане также не допускаются. Эти ограничения сохранены при последующей
проверке `gtnh-site-site (3).json`. Исправление повторяющихся ошибок для Auto-назначений описано
в `docs/shared-cracker-overload-fix-2026-10-09.md`.
